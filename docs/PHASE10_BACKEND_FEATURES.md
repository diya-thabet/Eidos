## Phase 1: Test Coverage Tracking

**Effort: 4 hours | Impact: High | Dependencies: pip install pytest-cov**

### Why

We have 2,119 tests but **no measurement of which lines they actually cover**. Without coverage data:
- We can't identify untested code paths
- We can't enforce minimum coverage in CI
- We don't know if new code is being tested

### What

#### 1.1 Add `pytest-cov` to dev dependencies

```toml
# backend/pyproject.toml
[project.optional-dependencies]
dev = [
    ...
    "pytest-cov>=5.0",
]
```

#### 1.2 Configure coverage in `pyproject.toml`

```toml
[tool.coverage.run]
source = ["app"]
branch = true
omit = ["*/__init__.py", "*/tests/*"]

[tool.coverage.report]
fail_under = 80
exclude_lines = [
    "pragma: no cover",
    "if TYPE_CHECKING:",
    "raise NotImplementedError",
    "if __name__ == .__main__.:",
]
show_missing = true
```

#### 1.3 New API endpoint: `GET /repos/{id}/snapshots/{sid}/coverage`

Reads `coverage.json` (generated by `pytest --cov-report=json`) and returns:

```json
{
  "snapshot_id": "s1",
  "overall_percent": 87.3,
  "branch_percent": 81.5,
  "covered_lines": 18234,
  "missing_lines": 2647,
  "files": [
    {"path": "app/api/repos.py", "percent": 95.2, "missing": [123, 145]}
  ]
}
```

#### 1.4 CI integration

Update `.github/workflows/test.yml`:

```yaml
- name: Run tests with coverage
  run: pytest --cov=app --cov-report=xml --cov-report=term --cov-fail-under=80
```

### Deliverables

- `pyproject.toml` updated
- `app/api/coverage.py` new endpoint (~80 lines)
- `tests/test_coverage_api.py` (~10 tests)
- Coverage badge in README
- CI fails if coverage < 80%

## Phase 3: Audit Log

**Effort: 5 hours | Impact: High | Dependencies: None**

### Why

Enterprise compliance (SOC 2, ISO 27001) requires **who did what, when**. Current system has zero audit trail. Critical for:
- Detecting unauthorized access
- Compliance reporting
- Debugging "who deleted that snapshot?"

### What

#### 3.1 New DB model: `AuditEvent`

```python
class AuditEvent(Base):
    __tablename__ = "audit_events"

    id: Mapped[int] = mapped_column(primary_key=True)
    timestamp: Mapped[datetime]
    user_id: Mapped[str | None]  # Null for unauthenticated/system
    user_email: Mapped[str]      # Snapshot of email
    action: Mapped[str]          # "repo.create", "snapshot.delete", etc.
    resource_type: Mapped[str]   # "repo", "snapshot", "user", ...
    resource_id: Mapped[str]
    metadata_json: Mapped[str]   # Extra context (IP, user agent, payload)
    ip_address: Mapped[str]
    success: Mapped[bool]

    __table_args__ = (
        Index("ix_audit_user_time", "user_id", "timestamp"),
        Index("ix_audit_action_time", "action", "timestamp"),
    )
```

#### 3.2 Audit middleware

A FastAPI middleware that:
- Captures method + path + user + IP for every mutation (POST, PUT, PATCH, DELETE)
- Skips read-only GETs (configurable)
- Records 4xx/5xx as `success=False`

```python
# app/core/audit.py
async def audit_middleware(request, call_next):
    response = await call_next(request)
    if request.method in ("POST", "PUT", "PATCH", "DELETE"):
        await record_audit_event(request, response)
    return response
```

#### 3.3 New endpoints

```
GET /admin/audit-log              # Query audit events (admin only)
GET /admin/audit-log/export       # Export as CSV
```

Query params: `user_id`, `action`, `resource_type`, `from_date`, `to_date`, `limit`, `offset`.

#### 3.4 Configurable retention

Add `EIDOS_AUDIT_RETENTION_DAYS=90` config. Background cleanup task (called from existing retention module).

### Deliverables

- `app/storage/models.py`: `AuditEvent` model
- `app/core/audit.py`: middleware (~120 lines)
- `app/api/admin.py`: 2 new endpoints
- `tests/test_audit.py`: ~25 tests
- Updated middleware registration in `main.py`

## Phase 4: API Key Scoping & Permissions

**Effort: 6 hours | Impact: High | Dependencies: None**

### Why

Current API keys are **all-or-nothing**. A CI key can do anything the user can do. Best practice: **least privilege** — each key has explicit scopes (e.g., "read snapshots only").

### What

#### 4.1 Extend `ApiKey` model

```python
class ApiKey(Base):
    # ... existing fields ...
    scopes: Mapped[str]    # Comma-separated: "read:snapshots,write:reviews"
    expires_at: Mapped[datetime | None]
    last_used_at: Mapped[datetime | None]
    usage_count: Mapped[int] = mapped_column(default=0)
```

#### 4.2 Define scope catalog

```python
# app/auth/scopes.py
SCOPES = {
    "read:repos": "List and view repos",
    "write:repos": "Create, update, delete repos",
    "read:snapshots": "List and view snapshots",
    "write:snapshots": "Create snapshots (ingest)",
    "delete:snapshots": "Delete snapshots",
    "read:analysis": "View symbols, edges, health",
    "write:reviews": "Submit PR reviews",
    "write:docs": "Generate documentation",
    "admin:users": "Manage users",
    "admin:plans": "Manage plans",
    "admin:audit": "View audit log",
    "*": "Full access (legacy compatibility)",
}
```

#### 4.3 Endpoint-level scope enforcement

Add a dependency:
```python
def require_scope(scope: str):
    async def _check(request: Request, user = Depends(get_current_user)):
        api_key_scopes = getattr(request.state, "api_key_scopes", "*")
        if "*" not in api_key_scopes and scope not in api_key_scopes:
            raise HTTPException(403, f"Missing scope: {scope}")
    return _check

# Apply to endpoints:
@router.delete("/{repo_id}/snapshots/{sid}",
               dependencies=[Depends(require_scope("delete:snapshots"))])
async def delete_snapshot(...): ...
```

#### 4.4 Updated endpoints

```
POST /auth/api-keys                # Now accepts {name, scopes: [...], expires_at}
GET  /auth/api-keys/{id}/usage     # Show usage stats
```

### Deliverables

- `app/auth/scopes.py`: scope catalog (~50 lines)
- `app/auth/dependencies.py`: `require_scope` dependency
- `app/storage/models.py`: extended `ApiKey`
- `app/api/auth.py`: updated key creation

## Phase 8: Health Score & History

**Effort: 6 hours | Impact: High | Dependencies: None**

### Why

We have 66 individual rules but **no overall health score**. Teams want a single number to track over time:
- "We went from 72 to 81 last month"
- Compare repos: "Repo A: 85, Repo B: 67"
- Trigger alerts: "Score dropped >5 points"

### What

#### 8.1 Score algorithm

```python
def compute_health_score(snapshot_data) -> HealthScore:
    """Returns a 0-100 score with category breakdown."""
    # Weights (sum = 100)
    weights = {
        "complexity": 20,    # avg cyclomatic, % long functions
        "design": 20,        # SOLID violations, coupling
        "duplication": 10,   # clone count
        "dead_code": 10,     # % unreachable
        "documentation": 5,  # % documented public APIs
        "naming": 5,         # naming violations
        "security": 15,      # security findings
        "dependencies": 10,  # outdated, missing pins
        "tests": 5,          # has tests folder
    }
    # Each category: 100 - (penalty per violation, capped)
    # Final: weighted sum
```

#### 8.2 New DB model: `HealthScoreHistory`

```python
class HealthScoreHistory(Base):
    __tablename__ = "health_scores"

    id: Mapped[int] = mapped_column(primary_key=True)

        ForeignKey("repo_snapshots.id", ondelete="CASCADE"), unique=True)
    overall: Mapped[float]

    grade: Mapped[str]  # A, B, C, D, F

```

#### 8.4 Auto-compute on ingestion

## Phase 9: SBOM Generation (CycloneDX)

**Effort: 5 hours | Impact: High | Dependencies: None (pure JSON)**

### Why

**Software Bill of Materials (SBOM)** is now mandatory for many enterprise customers (US Executive Order 14028, EU Cyber Resilience Act). We already parse dependencies — generating CycloneDX JSON is purely formatting.

### What

#### 9.1 CycloneDX 1.5 generator

```python
# app/exports/sbom.py
def generate_cyclonedx(
    snapshot_id: str,
    repo_name: str,
    dependencies: list[dict],
) -> dict:
    """Generate CycloneDX 1.5 SBOM."""
    return {
        "bomFormat": "CycloneDX",
        "specVersion": "1.5",
        "serialNumber": f"urn:uuid:{uuid.uuid4()}",
        "version": 1,
        "metadata": {
            "timestamp": datetime.now(UTC).isoformat(),
            "tools": [{"name": "Eidos", "version": "1.0.0"}],
            "component": {
                "type": "application",
                "name": repo_name,
                "version": snapshot_id[:7],
            },
        },
        "components": [
            {
                "type": "library",
                "name": dep["name"],
                "version": dep["version"],
                "purl": _to_purl(dep),  # Package URL spec
                "scope": "required",
            }
            for dep in dependencies
        ],
    }
```

## Phase 10: Incremental Health Analysis

**Effort: 6 hours | Impact: High | Dependencies: None**

### Why

Currently, every health check runs ALL rules on ALL symbols. For a 50K-symbol repo, that's slow. We already have **incremental file analysis** (`compute_changed_files`) — we should do the same for health checks.

### What

#### 10.1 Persist health findings per symbol

Add `HealthFindingPersisted` model that stores findings per symbol with a stable hash:

```python
class HealthFindingPersisted(Base):
    __tablename__ = "health_findings"

    id: Mapped[int] = mapped_column(primary_key=True)
    snapshot_id: Mapped[str]
    symbol_fq_name: Mapped[str]
    rule_id: Mapped[str]
    severity: Mapped[str]
    message: Mapped[str]
    file_path: Mapped[str]
    line: Mapped[int]
    fingerprint: Mapped[str]   # hash(symbol_id + rule_id + content)
```

#### 10.2 Change detection

```python
async def incremental_health_analysis(
    db: AsyncSession,
    new_snapshot_id: str,
    prev_snapshot_id: str | None,
    changed_files: set[str],
) -> list[HealthFinding]:
    """Only re-run rules on changed files; copy unchanged findings."""
    if prev_snapshot_id is None:
        return run_all_rules(graph)  # Full scan

    # Copy unchanged findings
    await copy_unchanged_findings(
        db, prev_snapshot_id, new_snapshot_id, changed_files,
    )

    # Run rules only on changed-file symbols
    changed_symbols = [s for s in graph.symbols if s.file_path in changed_files]
    new_findings = run_rules_on_subset(graph, changed_symbols)

    return new_findings
```

#### 10.3 Diff endpoint

```
GET /repos/{id}/snapshots/{sid}/health/diff/{prev_sid}
```

Returns:
```json
{
  "added_findings": [...],
  "fixed_findings": [...],
  "unchanged_findings": 234
}
```

Useful for PR reviews: "this PR introduced 3 new errors and fixed 2".

### Deliverables

- `app/storage/models.py`: `HealthFindingPersisted` model
- `app/analysis/incremental_health.py`: ~250 lines
- `app/api/analysis.py`: extended health endpoint, new diff endpoint
